The decompiler

Hover a blok and every piece of source it owns inverts at once, including pieces that sit paragraphs apart. A blok is not a slice of text; it is a set of ranges. That is the only way a rule stated in three places can be one thing you edit once. Click to pin a highlight, click again to release.

What the multi-range mapping changes

  • A blok owns a set of ranges, not one span. Block { blok_id, ranges: [[start,end], …] }. Every downstream feature inherits this: failure attribution can point at three places at once, and editing the blok rewrites all of them.
  • Fragmentation becomes a visible defect. A rule scattered across four paragraphs is a bug in the prompt, and the fragment count on the card is the first honest measure of how disorganised a prompt is.
  • Recompiling defragments. Once fragments are one blok, the compiler emits the rule once, in one place. That is a real, measurable improvement to the prompt that costs the user a single click.
  • Highlight uses ink inversion, not a colour. Green, red and amber stay reserved for pass, fail and drift; a highlight that borrowed one of them would break the semantics the whole system depends on.
