Illustration system

Eight geometric SVGs built from the product's own vocabulary: cards, spans, connectors, cells. Two-pixel strokes matching the UI border weight, drawn in currentColor so they invert with the theme instead of needing a second set. No characters, no gradients, no raster.

Same files, both themes. Nothing is re-exported.

Rules that keep this from turning into stock art

  • Draw the product, never a person. Every illustration is a diagram of the data model: bloks, spans, connectors, cells, versions. It teaches while it decorates, which is the only reason a workbench earns illustration at all.
  • currentColor and CSS variables only. No baked hex, no gradients, no shadows inside the SVG. One file serves both themes and any future accent change.
  • 2px strokes, square caps, mitre joins. Same weight as the UI borders, so the art reads as part of the interface rather than pasted onto it.
  • Straight segments and right angles only. One exception: the check mark and the badge outline. Curves would break the family instantly.
  • Saturation is still reserved. Green and red appear in illustrations only when they mean pass and fail. No decorative colour, ever.
  • Under 2KB each, inline, no sprite sheet. These are eight shapes, not an asset pipeline.

Where illustration is banned

  • Any surface showing live data. The results matrix, the compiled prompt, the canvas with bloks in it. Illustration appears only where there is nothing to read.
  • Loading and transitional states. A skeleton is faster to parse and does not need to be looked at twice.
  • Anything a person sees more than twice a week. Illustration in a daily-use tool becomes furniture on the third viewing and clutter on the tenth.
  • As a substitute for an empty-state action. The drawing is the smaller half; the button underneath it is the point.
