Logo v2; real outlines, real morph

The previous version stacked rectangles and rotated them, which is why the joints looked broken. This version draws each glyph as one closed outline plus its counter, with the same number of vertices in both states, and interpolates every point. Corners stay mitred the whole way through. The A is italic, so the 4's diagonal keeps going instead of standing up.

How the 4 becomes an italic A

The outer contour of the 4 has nine vertices. Three of them sit stacked at the bottom-left corner of the crossbar, doing nothing. In the A those three separate and become the left leg, so the leg grows out of the crossbar rather than fading in. The diagonal never resets; it stays the same edge, only steeper, which is why the italic slant matters.

4 : (18,14)(32,14)(32,50)(25,50)(25,41)
    (8,41)(8,41)(8,41)(8,34)
A : (28,14)(34,14)(44,50)(36,50)(31,41)
    (21,41)(16,50)(8,50)(16,36)

The counter morphs too

Both glyphs have exactly one triangular counter, so it maps one to one: the 4's counter leans and opens into the A's. Both contours live in a single path with fill-rule: evenodd, so the hole is cut rather than painted.

The 1 to italic I is a parallelogram: the flag retracts into the top-left corner while the whole stem slants. It is a small move by design; a 1 and an I are close cousins and forcing more motion reads as a glitch.

Cost of this approach

It needs about 40 lines of JavaScript, where the rectangle version needed none. That is the price of clean joints; CSS cannot interpolate an outline shape reliably across browsers. Everything degrades safely: with JS off, the mark renders as a static 41.

Unchanged from v1

The accessible name stays 41Prompts in both states. Keyboard focus triggers the same animation as hover. prefers-reduced-motion collapses the duration. Below roughly 20px the counters close up, so the favicon should stay a static filled plate.
