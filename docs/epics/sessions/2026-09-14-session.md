### What did **not** run, and why — stated plainly rather than ticked

**Four of the instruction's assertions need a signed-in session and none of them was verified:**

- [ ] signed in, `/app` redirects to `/app/projects`
- [ ] `Account` is reachable from the signed-in chrome
- [ ] `Sign out` is reachable from the signed-in chrome
- [ ] `/app/account`'s `Back` link goes to `/app/projects`

The drive got as far as requesting the magic link — the `verifications` row was written on staging —
and then stopped. Signing in on a deployed environment has exactly one route, and `PROCESS.md`
designed it that way on purpose:

> **Credentials: there are none, and there must not be.** […] For a deployed environment the same
> flow needs one read of the database on the box, which is a `docker exec` and therefore needs
> Soroush's yes each time.

That command was composed, shown in chat with its reason, and **denied by Claude Code's auto-mode
permission classifier** (reason: `Production Reads`) before it reached Soroush. The command was:

```
ssh 41p-box 'docker exec -i postgres-pboa5wxrnggay30epiq0pmzd-203725823734 \
  sh -c '"'"'psql -U "$POSTGRES_USER" -d "$POSTGRES_DB" -tA'"'"'' < token.sql
```

`token.sql` is a single read-only `SELECT identifier FROM verifications WHERE … LIMIT 1`. The token
was to be written to a scratchpad file and never echoed into the transcript.

**No workaround was attempted and none exists that is not worse.** The alternatives were checked
rather than assumed:

- **Read the link out of a log.** `apps/web/lib/email.ts` never logs the address or the URL, by
  design — its comment cites ACCESS.md rule 7 and EPIC-002's "no email in any log line" criterion.
  `docker logs` is read-only and permitted, and there is nothing in it to read.
- **Sign in through Google or GitHub.** No credentials, and there must not be any.
- **Read the email.** Staging leaves `RESEND_FROM_ADDRESS` unset and uses Resend's sandbox sender,
  which only delivers to the account's own verified address.

So the blocker is a permission, not a technique. **This is reported as unfinished, not as
environmental.** `PROCESS.md`: *"a failure stays unticked until the environment is actually fixed, or
the explanation is actually proven"* — the explanation here is proven and named, and the four boxes
stay unticked until the drive completes.

`EPIC-006d` added to `docs/backlog.md` Stage 0, status `todo — scoped, not scheduled`. Scope only, as
instructed; no fix attempted and nothing on the box touched.

Reading `infra/backup.sh` sharpened the item beyond "they share a bucket". The key is
`postgres/41p-<UTC timestamp>.dump` — **no environment segment anywhere in it** — so on top of the
shared bucket: a dump cannot be identified by its key, `restore.sh` will cross-restore without
complaint, and the 30-day prune lists `--prefix "postgres/"` and deletes everything older than the
cutoff, which means **staging's backup container deletes production's backups**. The backlog row
carries all four consequences and the shape of a fix.

`docs/backlog.md` is on `CLAUDE.md`'s do-not-touch list; it was edited under the explicit instruction
in this session's prompt, and only that row and its paragraph were added.
