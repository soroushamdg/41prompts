# Plan — EPIC-054: `fortyone`, and the prompt arrives in a Python process

Written 2026-09-17, before any code, per `CLAUDE.md` ("Plan first… stop and show the plan") and
`docs/AUTONOMOUS.md` step 2.

## What this is, in one line

Port `@41prompts/sdk` to Python with no dependencies, and prove the port agrees with the original
everywhere agreement is load-bearing.

## The order, and why it is this order

**1. `_canonical.py` first, against a golden generated from Node.** It is the only file where being
nearly right yields a package that refuses every artifact it is handed, and the failure presents as
`hash_mismatch`, which means *somebody served you the wrong document*. Everything downstream is
worthless until this is byte-exact.

*De-risked before this plan was written.* A prototype of the ECMA-262 `Number::toString` reformatter
was run against 37 values emitted by `node -e 'JSON.stringify(x)'` — integral floats, both exponent
thresholds (1e21 and 1e-7), `-0`, `5e-324`, `2**53`, `1/3`, `Math.PI` — **0 mismatches**. The
approach is: take Python's `repr`, which is also shortest-round-trip, decompose it into (digits, n),
and re-render by ECMA-262 §6.1.6.1.20's five cases. The committed golden will be larger and will
include random doubles.

**2. `_sha256` is not written.** `hashlib` is standard library. `packages/core` writes its own only
because core may have no dependency *and no `node:crypto`*; Python has no such gap. This is the first
divergence-table row that is an absence.

**3. `_bind.py`** — `occurrences_in_text` and `bind_variables`, ported with the three traps intact and
JavaScript's `\s` spelled out as an explicit class.

**4. `_verify.py`** — `read_marker`, `read_artifact`, `check_artifact`, mirroring `verify.ts` case for
case, including the two-check split (hashes to its own address; that address is the one the marker
names) and the `expected_hash=None` case for a bundled artifact.

**5. `_disk.py`** — the same record and the same directory as `disk.ts`, atomic write, `SAFE_ID`
guard, everything best effort.

**6. `_network.py`** — `urllib.request`, two GETs, conditional on `ETag`, the same `FetchOutcome`
shapes, a timeout that cancels rather than races, and nothing that raises.

**7. `__init__.py`** — the client: memory map, one in-flight request per prompt (a `threading.Lock`
plus a per-prompt event), the jittered daemon `Timer`, `resolve`, `refresh`, `close`, plus
module-level `resolve` and `configure`.

**8. Tests.** Canonical golden, verify, bind, offline, stale, never-raises, telemetry, packaging,
disk cross-language, divergence table, alias manifest.

**9. The edges.** `py.typed`, the alias distribution, `forbidden-words.mjs`, the CLI's note, the
README with the divergence table, `REUSE.toml`, the mirror dry run's path list.

**10. Gates, then the drive, then merge, then the report.**

## The five things most likely to go wrong, and what is done about each

1. **The encoding disagrees.** Golden from Node, generated by a committed command, including random
   doubles. Already prototyped at 0/37 mismatches.
2. **`\s` differs between the two regex engines.** Spelled out explicitly; a test feeds `﻿` and
   `\x85` between the braces and asserts the two languages agree about which is a variable.
3. **The daemon thread keeps a test hanging or dies mid-write.** `close()` in a fixture teardown, and
   the write is temp-plus-rename so a killed writer cannot corrupt a cache.
4. **`mypy --strict` over the generated bindings passes for the wrong reason.** A negative control:
   the same check with a deliberately wrong argument type must fail.
5. **The drive's Python cannot import `fortyone`.** It runs the interpreter with `PYTHONPATH` at
   `sdks/python`, and asserts the module file it loaded is that one — not a wheel from somewhere else.
